# P0 + P1 Baseline Bot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Cargo workspace with a deterministic, latency- and fee-aware simulated BTC/USDT exchange, plus a market-making bot behind a `Venue` trait. It must run end to end with stand-in components. It also includes the scaffolding (interface, `todo!()` stubs, ignored tests as the spec, a guide) for the three components the owner will write: order book, market maker and risk.

**Architecture:**
- **Discrete-event simulation.** A priority queue keyed by `(deliver_at, seq)` drives:
  - the matching engine
  - a synthetic market (random-walk fair price, a refreshing liquidity provider, Poisson takers with an informed fraction)
  - message delivery between bot and exchange, delayed by the configured one-way latency
- **Bot loop.** `SimVenue` wraps the simulation behind the `Venue` trait. The `app` crate runs the bot loop (book → strategy → risk → tracker → venue), tracks PnL and prints the summary.
- **Swappable components.** Book, strategy and risk are traits with a stand-in implementation plus an owner (`mine`) implementation, chosen by CLI flag.

**Tech Stack:**
- Rust stable (edition 2024)
- `rand` + `rand_chacha` (seeded RNG)
- `clap` (derive) for the CLI
- `proptest` for property tests
- Makefile for shortcuts

**Spec:** [docs/VISION.md](../../VISION.md) §4–§5, [docs/initiatives/P0-setup.md](../../initiatives/P0-setup.md), [docs/initiatives/P1-baseline-bot.md](../../initiatives/P1-baseline-bot.md)

## Global Constraints

- **Prices, quantities and cash are integers** (`i64` newtypes), never floats. Floats are allowed only for synthetic-market randomness parameters (rates) and for display.
- **Instrument BTC/USDT:** tick = 0.01 USDT, lot = 0.00001 BTC.
  - `Price` is counted in ticks and `Qty` in lots.
  - `Cash` is counted in units of 1e-7 USDT, so `price_ticks * qty_lots` is exactly a `Cash` value.
  - `CASH_UNITS_PER_USDT = 10_000_000`.
- **Determinism:** the same seed gives an identical `Summary`.
  - Seeded `ChaCha8Rng` only. No wall-clock reads, and no iteration over `HashMap`/`HashSet` (lookup only).
  - Scheduler ties are broken by insertion sequence number.
- **Fees** are in parts per million of notional: `fee = notional * ppm / 1_000_000` (Rust `/`, truncating toward zero). A negative ppm means a rebate.
  - Defaults: maker 200 ppm (0.02%), taker 500 ppm (0.05%).
- **Latency** is one-way, in nanoseconds, applied to every bot→exchange and exchange→bot message. The default is 1 ms (`1_000_000` ns); `0` is valid.
- **The bot sees only what `Venue` delivers.** No access to exchange internals.
- **Owner-facing code** (`mine.rs` stubs, guides, owner tests) uses simple Rust: concrete types, no generics or lifetimes beyond the given trait signatures, no `unsafe`, no macros beyond the standard ones.
- **The summary must include the venue, latency and fee lines, and PnL both before and after fees** (VISION §5.2).
- `make check` (fmt check + clippy `-D warnings` + tests) must pass at the end of every task.
- **Branch:** all work happens on branch `p0-p1-baseline`, created from `main` at the start of Task 1.

## Review Focus

Five inputs or failure modes the spec implies that are most likely to bite. Each one gets a test in the task that owns the code:

1. **A cancel that loses the race to a fill.** The exchange rejects it with `UnknownOrder`. The tracker must not double-count, crash, or leave a ghost order. → Task 6 (`cancel_after_fill_is_rejected_unknown`), Task 9 (`unknown_order_reject_after_fill_is_noop`).
2. **An empty or one-sided book** (at startup, or after a taker sweeps one side). The strategy places nothing, risk returns `NoReferencePrice`, and PnL marks at the last known mid. → Task 3 (`market_order_sweeps_side`), Task 10 (`stand_in_quotes_nothing_without_two_sided_book`), Task 12 (`unrealized_uses_last_known_mark`).
3. **A market order larger than all resting liquidity.** It partially fills and the remainder is `Cancelled`, with no panic and no resting market order. → Task 3 (`market_order_remainder_cancelled`).
4. **A position flipping through zero in one fill** (long 100 → short 50). Average-cost PnL stays exact. → Task 12 (`position_flip_realizes_and_reopens`).
5. **Degenerate CLI values:** latency 0, fees 0 and negative maker fee are valid; `quote_lots <= 0`, `duration_secs == 0` and `half_spread_ticks < 0` are startup errors with a message, not panics. → Task 13 (`config_validation`).

### Task 3: Matching engine with fees (P1 1.1–1.4)

**Files:**
- Create: `crates/exchange/src/engine.rs`
- Test: inline tests + `crates/exchange/tests/engine_props.rs` (proptest)

**Interfaces:**
- Consumes: Task 2 types.
- Produces:
  - `pub struct MatchOutput { pub exec: Vec<(TraderId, ExecEvent)>, pub trades: Vec<MarketData> /* Trade only */, pub book_changed: bool }`
  - `MatchingEngine::new(fees: FeeSchedule) -> Self`
  - `MatchingEngine::submit(&mut self, cmd: &Command) -> MatchOutput`
  - `MatchingEngine::snapshot(&self, depth: usize) -> BookSnapshot`
  - `MatchingEngine::best_bid(&self) -> Option<Price>`, `best_ask(&self) -> Option<Price>`
  - `MatchingEngine::resting_orders(&self, trader: TraderId) -> Vec<OrderId>` (sorted)
  - Exec events are routed to `id.trader` of each order involved.

**Rules:**
- **Validation:** `qty <= 0` → `Reject InvalidQty`; limit `price <= 0` → `Reject InvalidPrice`; an id that is resting, or was ever seen, → `Reject DuplicateId`.
- **Accepted orders:** emit `Ack` first. Then match at the resting order's price, by price-time priority (FIFO per level).
- **Each match:**
  - emits a `Fill` to the taker (`Liquidity::Taker`, taker fee) and to the maker (`Liquidity::Maker`, maker fee). Fees are computed with `fee(notional(price, qty), ppm)` and `leaves` is the remaining quantity.
  - emits one `MarketData::Trade` with `aggressor` = taker side.
- **Remainders:** a limit remainder rests. A market remainder emits `Cancelled { leaves }`.
- **Cancel:** of a resting id → `Cancelled { leaves }`. Of an unknown, filled or already-cancelled id → `Reject UnknownOrder`, routed to `id.trader`.
- **Data structures:** `BTreeMap<Price, VecDeque<Resting>>` per side; `HashMap<OrderId, (Side, Price)>` for lookup only; a `HashSet<OrderId>` of seen ids.

### Task 6: Simulation with latency (P1 1.6, 1.8, 1.9)

**Files:** Create `crates/exchange/src/sim.rs`; Test: `crates/exchange/tests/sim.rs`

**Interfaces:**
- Consumes: `MatchingEngine` (Task 3), `Scheduler` (Task 4), `SyntheticMarket` (Task 5).
- Produces:
  - `pub struct SimConfig { pub seed: u64, pub duration_ns: u64, pub latency_ns: u64, pub fees: FeeSchedule, pub synthetic: SyntheticConfig, pub depth: usize }` (Clone, Debug). `Default`: seed 42, duration 3_600e9, latency 1_000_000, fees {200, 500}, synthetic default, depth 10.
  - `pub struct Simulation`:
    - `new(cfg: SimConfig) -> Self`
    - `now(&self) -> Timestamp`
    - `send(&mut self, cmd: Command)`: from the bot; arrives at the exchange at `now + latency`
    - `next_bot_event(&mut self) -> Option<(Timestamp, BotEvent)>`
    - `inject(&mut self, at: Timestamp, cmd: Command)` (pub, for tests and scenarios): arrives at the exchange exactly at `at`
    - `exchange_mid(&self) -> Option<Price>`

**Rules:**
- **Internal event enum:** `FairStep | LpRefresh | TakerArrival | ToExchange(Command) | ToBot(BotEvent)`.
- **When `synthetic.enabled`:** schedule `LpRefresh`@0, `FairStep`@interval and `TakerArrival`@first delay. Each event reschedules itself.
- **Processing:**
  - `ToExchange` → `engine.submit`. Exec events whose `id.trader == BOT` become `ToBot(Exec)`. Trades become `ToBot(Market(Trade))`. Both are scheduled at `now + latency`.
  - After processing *any* event: if the book changed, schedule one `ToBot(Market(Snapshot(engine.snapshot(depth))))` at `now + latency`. Send at most one snapshot per processed event.
- **Synthetic commands** (LP refresh, takers) are submitted to the engine at the current time; the synthetic traders have zero latency. `LpRefresh` passes `engine.resting_orders(LIQUIDITY)`. Rejections for synthetic traders are dropped.
- **`next_bot_event`** pops and processes events until it pops a `ToBot`, which it returns. It returns `None` once the next event's time is greater than `duration_ns`. `now` advances to each popped event's time.
